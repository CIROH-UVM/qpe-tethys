# NGPE ToolPropertiesPanel Refactor — Changes Summary (2026-04-20)

## Overview

This document summarizes all changes made to the NGPE app on 2026-04-20, building on Pat's original Tool/ToolPropertiesPanel architecture. The refactor was driven by team feedback to fix ReactPy state management issues, complete missing property type implementations, and wire up Noah's data downloaders.

---

## Files Changed

### 1. `tools/tool.py` — Minor update

**What changed:**
- `get_properties()` return type changed from `Dict[str, Any]` → `List[Dict[str, Any]]`
- Added docstring documenting the agreed architecture (use_ref for Tool, use_state for props, callbacks)

**Why:**
- Team agreed simpler list shape is fine for now; the `{'properties': [...]}` wrapper dict was unnecessary since no other keys were needed yet.

---

### 2. `tools/LoadDatasetTool.py` — Two changes

#### a) `get_properties()` simplified
- Returns a plain list instead of `{'properties': [...]}`
- Fixed `region` property type from `'str'` → `'list'` (it has an options list, so it should render as a dropdown)
- Wrapped `self.RFC_BBOXES.keys()` in `list()` for safe serialization

**Why:** Pat noted the region type was wrong in the team Q&A. Team agreed to drop the wrapper dict.

#### b) `_download_raster()` / `_download_points()` — stubs replaced with Noah's code
- Added imports of Noah's `mrms.get_data()` and `madis.get_data()` from `qpe-tethys/data/` via `sys.path`
- Created `__init__.py` in `qpe-tethys/data/` to enable package imports
- Each method is an **adapter** that converts Noah's output format to Pat's DataLayer contract:

**MRMS adapter (`_download_raster`):**
1. Converts region string → bbox dict (Noah expects `{'min_lon', 'max_lon', 'min_lat', 'max_lat'}`)
2. Calls `noah_mrms.get_data(start, end, bbox)`
3. Extracts DataArray from Dataset: `ds['cref']`
4. Removes time dimension: `da.isel(time=0)`
5. Renames dims: `(latitude, longitude)` → `(y, x)`
6. Sets `attrs['bbox']` from coordinate bounds
7. Sets `attrs['crs'] = 'EPSG:4326'`
8. Replaces MRMS sentinel values (-99) with NaN (not 0, to preserve transparency)

**MADIS adapter (`_download_points`):**
1. Converts region string → bbox dict
2. Calls `noah_madis.get_data(start, end, bbox, crs_out='EPSG:4326')`
3. Renames column: `precipAccum` → `value`
4. Converts units: mm → inches (`value / 25.4`)
5. Adds `qc_flag = 9` (No QC — Noah hasn't implemented QC extraction yet)
6. Clamps negative values to 0
7. Converts `datetime` column from `pandas.Timestamp` → `str` (fixes JSON serialization error)

**Why:** Team agreed to wire up Noah's existing downloaders after the panel refactor was stable.

**Note:** Noah's MRMS module currently provides CREF (composite reflectivity in dBZ), not QPE precipitation in inches. The adapter handles this by replacing sentinel values with NaN. When a true QPE product is available, the adapter will need updating.

### 3. `components/ToolPropertiesPanel.py` — Rewrite (Pat's architecture, fixed wiring)

#### What stayed from Pat's code (preserved):
- Panel concept and right-side layout
- All styling (colors, spacing, fonts, border-radius, etc.)
- `get_properties()` driving the UI — Pat's key design idea
- Factory pattern for change handlers (Pat used `cur_prop`, we use `make_change_handler` with default arg capture)

#### What changed:
- **Zero hooks** inside the panel — it is now a pure render function
  - Pat's version broke because ReactPy needs the same number of hooks every render. With no tool selected = zero hooks, after tool selected = multiple hooks. ReactPy doesn't allow this.
  - Pat identified this problem himself (see his commented-out code and notes about `_Memo` errors)
- **State lifted to `app.py`** — panel receives `tool_props`, `tool_values`, `on_property_change`, `on_run_tool`
- **Implemented all three property types:**
  - `'list'` → `<select>` dropdown (Pat's original, now callback-driven instead of direct mutation)
  - `'str'` → `<input type="text">` (was "Not yet implemented" in Pat's version)
  - `'datetime'` → `<input type="datetime-local">` (was "Not yet implemented" in Pat's version)
- **Added "Run Tool" button** at bottom of panel
- **Removed dead code** after the `return` statement (lines 111-126 were unreachable)

**Why:** Team agreed on the callback pattern (same pattern already used for LayerCard). Pat preferred having the Run button in the panel (option 2 from team discussion).

---

### 4. `app.py` — State management refactored

#### Added:
- `tool_ref = use_ref(None)` — holds the mutable Tool instance without triggering re-renders
- `tool_props, set_tool_props = use_state(None)` — property definitions list from `get_properties()`
- `tool_values, set_tool_values = use_state({})` — dict of `{prop_name: current_value}` from user input
- `handle_property_change(prop_name, new_value)` — callback passed to panel; updates `tool_values` via functional updater
- `handle_run_tool(event)` — callback for "Run Tool" button; copies `tool_values` onto `tool_ref.current.properties`, calls `tool.run()`, adds resulting DataLayer to `active_layers`

#### Removed:
- Duplicate **region dropdown** and **datetime picker** from sidebar — these inputs now live in the ToolPropertiesPanel, driven by `LoadDatasetTool.get_properties()`
- `handle_load_data()` function — replaced by the panel-driven Run Tool flow
- `selected_region` and `selected_datetime` state hooks — no longer needed since inputs moved to panel

#### Simplified sidebar:
- Now just: "Load Data" button → Data Layers section
- Clicking "Load Data" creates a `LoadDatasetTool`, stores it in `tool_ref.current`, populates `tool_props` and `tool_values`

**Why:** Pat's feedback said tool inputs should live in the panel, driven by `get_properties()`. Team agreed on `use_ref` for Tool (mutable, no re-render) + `use_state` for the properties dict (drives UI). This matches the existing LayerCard pattern.

---

### 5. `data_layer/validation.py` — Minor update

**What changed:**
- `validate_raster()` now accepts an optional `value_max` parameter (default: 30.0 inches)
- `LoadDatasetTool.run()` passes `value_max=80.0` for CREF data (dBZ range 0-75)

**Why:** CREF data is in dBZ (0-75), not QPE inches (0-30). Without this, validation rejected valid radar data with "Max value 51.5 exceeds 30.0".

## Key OL/ReactPy Lessons Learned

1. **OL does NOT handle PATCHING existing children's props** — attempting to change `View` center/zoom via state destroyed the map entirely. The map view must remain static (same as reference qpe_builder app). Users zoom/pan manually.

2. **ReactPy requires consistent hook count per render** — Pat discovered this: hooks inside conditionals or loops break ReactPy. Solution: lift all state to the parent component and pass data + callbacks down.

3. **MRMS uses -99 as sentinel, not NaN** — replacing with 0 made everything transparent (since `_render_png` makes `arr == 0` transparent). Must replace with NaN instead.

4. **MADIS `datetime` column contains `pandas.Timestamp` objects** — `GeoDataFrame.to_json()` can't serialize these. Adapter converts to string.

5. **NOAA MADIS data retention is ~24-48 hours** — requests for older data return an HTML error page, causing `gzip.BadGzipFile`. MRMS on AWS S3 has longer retention.

## What Pat's Design Got Right (preserved)

- `Tool` base class with `get_properties()` describing UI controls
- `LoadDatasetTool` with `DATASET_CATALOG` and `RFC_BBOXES`
- Right-side panel concept for tool configuration
- Separation of concerns: `tools/` → `data_layer/` → `components/`
- The closure pattern for event handlers (`cur_prop` capture)
- The Noah boundary design (clean adapter methods in LoadDatasetTool)

## What Was Broken (fixed)

- Hooks inside conditional/loop (ReactPy inconsistent hook count crash)
- Direct prop mutation (`property['value'] = ...`) instead of state callbacks
- Missing property type implementations (`str`, `datetime`)
- No "Run Tool" button to execute the tool
- Download stubs not connected to Noah's actual code
- `region` property typed as `'str'` instead of `'list'`
